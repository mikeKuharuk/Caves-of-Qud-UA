# Українська граматика в грі (етап 5)

Гра складає частину тексту в коді з англійською граматикою: дієслова (`=subject.Does:hit=`),
артиклі, займенники, множину (`=turns.things:turn=`). Для таких рядків фреймворк дає дві офіційні
точки **[перевірено в коді]** (`docs/research/framework-212.md`):
- `[LanguageProvider("uk")]` — провайдер мови: артиклі, списки, числа, назви об’єктів;
- `[HasVariableReplacer(Lang = "uk")]` — власні `=змінні=`, які діють лише українською.

Цей документ описує, що мод додає, і синтаксис змінних для перекладачів.

## Що це відкриває

На 2026-09-29 у каталогах лишилося ~12 % слів, яким потрібна граматика:
- **повідомлення з англійською граматикою** (`Strings`, ~6,4 тис. слів);
- **процедурна історія** (`HistoricEvent`, євангелія й агіографії, фрески, ~6 тис.). Їй ще
  потрібен перекладений `HistorySpice.uk.json`: ~14 тис. слів, у статистиці каталогів не видно;
- **процедурні фрагменти** (`xtagTextFragments`, теги сіл, реліквії, рідини, біоми).

Частину таких рядків пакети `Strings-02…07` уже переклали обхідно: двокрапка, безособові
форми, «од.». Вони позначені `qud-ok: placeholder`. З граматикою їх можна переписати природніше.

## Синтаксис для перекладачів

Ключі латиницею, параметри — українські форми. `X` — об’єкт із шаблону (`subject`, `object`
тощо): ігровий об’єкт або іменник, який гра передає зі своїми займенниками (`GenderedNoun`,
наприклад частина тіла чи ефект).

| Змінна | Що дає | Приклад |
|---|---|---|
| `=X.v:<3 од.>:<2 мн.>[:<3 мн.>]=` | дієслово теперішнього чи майбутнього часу за особою й числом: гравець → 2 мн., множина → 3 мн. (якщо не дано — 3 од.), решта → 3 од. | `=subject.Name= =subject.v:б’є:б’єте:б’ють= …` |
| `=X.g:<ч.>:<ж.>:<с.>:<мн.>[:<гравець>]=` | форма за родом: минулий час, прикметник, дієприкметник, займенник. Гравець → мн., або п’ята форма, якщо її дано | `=subject.Name= =subject.g:упав:упала:упало:упали=.`, `=object.g:його:її:його:їх:вас=` |
| `=X.Name=` / `=X.name=` | ім’я в називному. Для гравця — «Ви»/«ви» (займенники набору `player`) | |
| `=N.plural:<1>:<2–4>:<5+>=` | слово за числом N (1 хід, 2 ходи, 5 ходів); N — ціле число | `=turns= =turns.plural:хід:ходи:ходів=` |
| `=X.p:<для гравця>:<для інших>[:<нікого>]=` | фраза, що називає X: для гравця, до якого звертаються на «ви», — перша форма, для інших — друга, де `@` — ім’я (як `=X.name=`). Замість дужок і двокрапок, які дають «розум (ви)». Третя форма — лише в хвостах шкоди (`Damage`), коли X немає; може бути порожньою | `=object.p:ваш розум:розум (@)=` |

Великий ключ (`=X.V:…=`, `=X.G:…=`) пише вибрану форму з великої літери.

Постпроцесори мода (дописуються до змінної через `|`):

| Постпроцесор | Що робить | Приклад |
|---|---|---|
| `\|uk.agree#X` | прикметник чоловічого роду (або «A і B») узгоджує з родом X: об’єкта (`#subject`, `#player`…), слова з коду (`#rank`) чи перекладеного іменника, який код передає текстом (`#primaryNoun` — назва рідини з нотаткою `qud-gender`) | `=modifier\|uk.agree#subject\|spaceAfter==subject.displayNameOnlyDirect=` → «Зла Марта» |
| `\|uk.f`, `\|uk.n`, `\|uk.pl` | прикметник у сталому роді, коли іменник дає сам шаблон | `тверді й =spice:…adjectives.!random\|uk.pl= рештки` |
| `\|uk.word` | англійське слово, яке код вставляє як є (ранги Птоха, префікси двійників), українською (`CodeWords`) | `=rank\|uk.word= Птоха` → «Скопа Птоха» |
| `\|uk.date` | дата, яку гра зберегла англійською («Friday, October 2, 2026 at 4:58:24 PM»), — українською | `=saveTime\|uk.date=` → «п’ятниця, 2 жовтня 2026 р., 16:58:24» |
| `\|uk.stem` | основа слова без закінчення, щоб скласти нове слово | `=subject.waterRitualLiquid\|uk.stem=о=player.siblingTerm=` → «водобрате» |
| `\|uk.stat` | ID характеристики, який код передає як є (вимоги навичок), — її назвою з таблиць рядків; коротка назва малого екрана проходить | `=stat_title\|uk.stat=` → «Спритність» |

Форми прикметника беруться з нотатки `uk-forms`, а коли її немає — з правильних закінчень: -ий →
-а/-е/-і, -ій → -я/-є/-і, порядкові цифрами 1-й → 1-ша, 3-й → 3-тя, 7-й → 7-ма. Непрозорі слова
(«Птохів», присвійні) правил не мають — для них потрібна нотатка.

Правила й поради (з перших трьох пакетів, 2026-09-29):
- у перекладі не лишаються англійські `Does`, `verb`, `a/an/the`, `things`, `pluralize`, займенникові
  змінні. `validate` приймає це, поки переклад і далі називає той самий об’єкт (`=subject.…=`);
- **відмінків назв поки немає:** назва зі змінної завжди в називному. Будуйте речення так, щоб вона
  була підметом або стояла після двокрапки, у дужках, після тире. Якщо відмінок явно потрібен,
  лишіть примітку `uk-case: object=acc` (gen, dat, ins, loc) — ці рядки поліпшимо, коли з’являться
  відмінки;
- **порядок слів рятує відмінок:** «Вас телепортує X», «Дорогу перегороджує X», «X не
  =object.v:відмикається:…= здалеку»;
- **гравець у третій особі.** Фрески й євангелія розповідають про гравця в третій особі: гра тоді
  вимикає «ви» (`Grammar.AllowSecondPerson`), і `v`/`g` дають гравцеві форми за його статтю, як будь-
  якому персонажеві;
- **займенники:** для об’єкта, який може бути гравцем, давайте в `g` п’яту форму («вас», «ваш»).
  Якщо підмет — власник, пишіть «свій/своя/своє/свої» без змінної;
- **`plural`:** форми можуть стояти в будь-якому відмінку («предмету:предметам:предметам»,
  «драма:драмів:драмів»). Коли число не показано, а важить лише «один чи кілька», пам’ятайте, що 21,
  31… дають першу форму. Списки (`=x.andList=`) рахувати не вміє;
- **складений підмет** («X та Y», «Ні ви, ні X») — дієслово в множині без змінної;
- форми можна писати з пробілами (гра це приймає, `validate` перевіряє і їх), але коротші форми
  читаються краще. Незмінні слова виносьте за змінну: `ще =subject.v:тримається:тримаєтеся=`;
- `=N.cardinal=` дає англійські слова — пишіть цифрами.

### Прикметники перед назвою

Гра сама ставить прикметники перед назвою предмета чи істоти: модифікації («rusted», «jacked»), розмір,
рідину («bloody»), «implanted». Такий прикметник перекладайте в **чоловічому роді**, у тій самій
розмітці, що й оригінал, і додайте нотатку з рештою форм:

```
COMMENT[k] = "uk-forms: іржава|іржаве|іржаві"    # жіночий|середній|множина
```

Мод узгоджує прикметник із родом об’єкта: «іржава сокира», «іржаве кресало», «іржаві чоботи».
Там, де прикметник стоїть окремо (список модифікацій), лишається чоловічий. Незмінні слова нотатки не
потребують, як і правильні прикметники на -ий/-ій: їх мод змінює сам. Нотатка потрібна, коли форма
неправильна або прикметник складений по-особливому. Два прикметники через «і» («заплямований кров’ю
і заплямований вином») узгоджуються кожен окремо. `validate` перевіряє, що форм рівно три.

## Що робить код (`mod/Grammar/`)

- `UkrainianProvider : TranslatorBase` з `[LanguageProvider("uk")]`:
  - артиклі порожні;
  - списки «А, Б і В» / «А, Б або В»;
  - генератор імен відкидає імена з українськими непристойними коренями (доповнює
    `Grammar.badWords`, яка знає лише англійські);
  - числівники (`UkrainianNumbers`): порядкові цифрами «12-й», словами «другий» (частини тіла),
    «один раз / двічі / тричі / N разів», кількісні — цифрами;
  - культура `uk-UA` для дат реального світу, регістру й двох сортувань (числа гра розбирає
    інваріантною культурою, тож розбору це не зачіпає);
  - без «a/the» перед назвами зон (`AddArticle`);
  - прикметник біому перед назвою зони узгоджується з її родом (`MutateZoneName`: рід із
    `NounGenders.ByWord` для всієї назви чи її кінця, а для однослівної власної назви — за закінченням);
  - «їдці» culling доповнено « » „ “ ” …: біля порожньої змінної гра прибирає пробіл і в лапках.
- `UkrainianTemplateKeys`: ключі шаблонів, англійські версії яких застосовують до нашого тексту англійську
  морфологію:
  - `nameStyle:TitleCase` пише з великої лише перше слово («Меч з каменю і вогню»);
  - `randomMeaningfulWord` і `wordRoot` працюють з українським стоп-списком і закінченнями;
  - `possessive`/`'s` нічого не роблять;
  - `zone.prosaic` дає назву місця без «the outskirts of»;
  - `factionaddress` і `descriptiveCategory` не множать англійськими правилами;
  - `disguise.name` — без «a».
- Види (`=x.species=`, `=x.apparentSpecies=`): гра передає англійський тег («human», «bear»), тож назва береться
  з таблиці `Species` (`CodeTables`, каталог `Code.Species.po`). `=player.species:voc=` дає кличний відмінок із
  нотатки `uk-voc:` («Вітаємо, людино»).
- Терміни звертання й спорідненості (`UkrainianTerms`): `formalAddressTerm`, `siblingTerm`, `offspringTerm`
  у кличному відмінку («друже»/«подруго», «брате»/«сестро», «сину»/«доню»), `personTerm`,
  `immaturePersonTerm`, `parentTerm` — у називному. Беруться за статтю самої особи, навіть гравця, до якого
  звертаються на «ви». Хіндрени мають свої: «оленю», «лане моя».
- `UkrainianCalendar`: день місяця «12-го Туум Ут» (15-те — «Іди» з таблиці), дати реального світу
  українською, `|uk.date` для часу збереження.
- `UkrainianReplacers` з `[HasVariableReplacer(Lang = "uk")]`: ключі `v`, `g` (для `GameObject` і
  `GenderedNoun`) і `plural` (для чисел).
- `UkrainianPostProcessors`: англійські `|article`, `|pluralize`/`|plural`, `|a.to.an` нічого не
  роблять, `|title` пише з великої лише першу літеру; власні `|uk.agree#X`, `|uk.f`/`|uk.n`/`|uk.pl`,
  `|uk.word` (таблиця вище).
- `UkrainianDescriptionBuilder`: прикметники перед назвою беруть рід об’єкта (таблиця
  `AdjectiveForms.g.cs`, її пише `qud.py build` з нотаток `uk-forms`, а для решти — правильні
  закінчення, `UkrainianForms.InflectRegular`).
  - Те, що код дописує до назви англійською (`E.AddAdjective("keen")`, `E.AddTag("[{{r|rusted}}]")`, «з …»,
    титули), білдер перекладає вже на вході: його `AddAdjective`, `AddTag`, `AddClause`, `AddWithClause`,
    `AddEpithet`, `AddTitle`, `AddMark` віртуальні, тож Harmony не треба. Таблиця — `Fragments`
    (`codescan.scan_fragments`, 45 фрагментів). Прикметник у ній чоловічого роду і далі узгоджується з
    назвою («відточена сокира»), позначка в дужках — безособова («[заіржавіло]»), «з …» — в орудному.
- `CodeWords` (`UkrainianWords.cs`): англійські літерали коду, які потрапляють у шаблони, — українською
  і з родом.
- `NounGenders.ByWord`: рід перекладених іменників за їхнім текстом, з усіх нотаток `qud-gender` (2 734
  слова). Ним `|uk.agree` узгоджує назву суміші рідин: «кривава солонувата вода».
- Рід об’єкта для `g`:
  1. гравець, до якого звертаються на «ви» → множина (або п’ята форма);
  2. іменований персонаж і гравець у третій особі → їхній рід у грі: male → ч., female → ж.,
     plural і they → мн. (D12), ey/em і неозайменники xe/ze/sie → с. (D11, D12);
  3. інше → граматичний рід назви з нашого перекладу (`qud-gender`), який збірка кладе в дані моду
     (`NounGenders.g.cs`);
  4. якщо його немає — ч.
- Чиста логіка (вибір форми, множина 1/2–4/5+, рід) — окремі класи без типів гри, щоб їх можна
  було тестувати без Unity.

## Harmony-патчі (`mod/Patches/`)

Код гри, до якого не дістати провайдером чи таблицями, ми патчимо Harmony (D13). Гра сама застосовує
всі класи з `[HarmonyPatch]` моду (`ModInfo.ApplyHarmonyPatches`), тож кожен патч стоїть осторонь, якщо гра
не українською (`Uk.Active`).

- `GrammarPatches`: статичні англійські помічники `Grammar` (`Pluralize`, `MakePossessive`, `A`,
  `IndefiniteArticle`, `MakeTitleCase`, `MakeTheList`, `ThirdPerson`, `PastTenseOf`). Слово з кирилицею
  лишається як є (без «s», «'s», «a», Title Case — лише перша велика); англійські слова з коду гри й далі
  йдуть за англійськими правилами, доки їхні речення не перекладено.
  - `Extensions.Things` — кількості, які код вписує в речення («5 turns», «3 rounds» перезарядки),
    — українською за таблицею `UkrainianThings` (15 слів, які передає код): «5 ходів», «ще 1 хід»,
    «12 драмів». Тому пропуск із такою кількістю в кодовій таблиці лишається: «Вас скалічено на {0}!».
    Українську назву (снаряди в `MissileWeapon`) рахує «стріла ×3».

- `BodyPatches`: частини тіла.
  - Назви дає `Bodies.uk.xml` (таблиця `Bodies` із `datatables.bodies_xml`, бо `Bodies.xml` гра не
    експортує).
  - Сторони гра дописує англійською (`Laterality.WithLateralityAdjective`: «left arm»). Для української назви
    вони стають прикметниками, узгодженими з іменником (`UkrainianLaterality`): «ліва рука», «верхній правий
    ріг», «права задня нога». `StripLateralityAdjective` знімає ті самі слова.
  - Порядковий числівник перед назвою, що повторюється (`GetOrdinalName`, `GetOrdinalDescription`), теж
    узгоджено: «друга голова».
  - Рід береться з нотатки `qud-gender` у таблиці `Bodies` (`NounGenders`, за останніми словами назви).
  - «Worn on» для спини й кистей прибрано: слоти «Спина», «Кисті» і так відрізняються від «Ліва кисть».
  - Частина тіла зберігає назву, яку отримала при створенні. Тому персонаж, створений до перекладу частин тіла,
    мав у спорядженні «Left Hand», «Worn on Back» (гра 2026-10-04). `BodyPart.ReadValues` (постфікс) дає такій
    частині українську назву й опис її типу зі сторонами, як `ChangeLaterality`, — лише коли збережена назва
    без сторін і є назвою типу (`Type` / `VariantType`); назву, яку дала мутація чи гра, не чіпає. У грі ще не
    бачено.

- `CodeText` + кодові таблиці: англійський текст, який пише сам C# гри, перекладається за таблицею
  `Code.<Таблиця>` (каталоги `Code.*.po`). Ключ — точний текст гри або шаблон із `{0}`, `{1}`… на місці того, що
  рахує код («-{0} DV» → «-{0} ЗУ»); багаторядковий текст іде рядок за рядком. Ключі знаходить у
  декомпільованому коді `tools/qudtr/codescan.py` (`work/decompiled/<збірка>`, `ilspycmd`); те, чого в таблиці
  немає, лишається англійським і раз пишеться в `Player.log` як `[uk-miss] таблиця: текст`. Нотатка `uk-agree`
  узгоджує переклад-прикметник з об’єктом.
  - `{n}` перекладу — це `{n}` ключа, хоч би де він стояв: пропуски одного ключа пронумеровані наскрізь (і в
    кількох полях ключа DidX), повтор того самого номера мусить збігтися з тим самим текстом. Пропуск не
    переходить на інший рядок.
  - Слово, яке рахує число з пропуску: `{0:хід:ходи:ходів}` — форми для 1, 2–4 і 5+ («через {0}
    {0:хід:ходи:ходів}» → «через 3 ходи»; дробове число бере форму 2–4). Валідатор вимагає, щоб у ключі був
    `{0}`, і рівно три форми. Лише в кодових таблицях: `string.Format` прочитав би `{0:…}` як формат числа.
  - Рядки з `\r\n` (вікно швидких клавіш інвентаря) шукаються без `\r`, і він лишається на місці.
  - Рядок без англійської (його дали таблиці рядків) у багаторядковому тексті не шукається: шаблон із самим
    пропуском («{0}: {1}») не зачепить українського рядка над англійським. Англійською не вважаються назва
    клавіші в кнопці (`{{keybind|Esc}}`) і змінна, яку гра ще не розгорнула (`=statistics[Toughness].title=`):
    такі рядки не перекладаються і не йдуть у `[uk-miss]`.
  - Пропуск, де стоїть ID характеристики («a difficulty 20 Toughness save»), отримує її назву з таблиць рядків
    («Витривалість», `StatisticBlueprint.DisplayTitle`). Тому в перекладі такий пропуск ставте в лапки після
    родового слова: «кидок «{2}»», «від характеристики «{0}»».
  - Пропуск, у якому стоїть слово з констант коду, перекладається за таблицею `Words` (`codescan.scan_words`):
    вкладки журналу (`JournalScreen.STR_*`), стійки довгих клинків, з чого подих (`GetBreathName`). Слово
    стоїть у тій формі, якої вимагає його речення (подих — у родовому: «конус отруйного газу»). Ті самі слова
    перекладають заголовок журналу (`JournalScreen.GetTabDisplayName`) і підказку вкладки
    (`FilterBarCategoryButton.SetCategory`); у самому коді назви вкладок лишаються англійськими, бо він їх
    порівнює.
- `EffectPatches`: назви й описи ефектів (`GetDescription`, `GetStateDescription`, `GetDetails` усіх класів
  ефектів, 264 методи) — через таблицю `Effects`, з узгодженням із носієм («отруєна», для «ви» — «отруєні»).
  Сканер бере те, що повертають ці методи, двічі: старим способом (ключі, перекладені раніше, лишаються) і
  через локальні змінні, поля й будівники в `if`/`else` (`computed_texts`), що додає пропущене: рядки Frenzied,
  Prone, LiquidCovered.

- `AbilityPatches`: назви й описи активних здібностей, які код дає англійською
  (`AddMyActivatedAbility("Intimidate", …)`, «Clone [3 left]»), — через таблицю `Abilities`
  (`codescan.scan_abilities`).
  - Запис здібності зберігає назву, а панель здібностей, список, вікна прив’язки клавіш і «не можна
    використати» читають її звідти. Тому назва перекладається там, де потрапляє в запис:
    `ActivatedAbilities.AddAbility`, `GameObject.SetActivatedAbilityDisplayName` і
    `ActivatedAbilityEntry.Read` (збереження, зроблене англійською).
  - Сканер знаходить літерали, локальні змінні (і ті, що ростуть: «Fly» → «Fly ({0})»), поля класу та його
    підкласів (`UrchinBelcher`: `CommandName`), методи підкласів (`GetCommandDisplayName` подихів) і ланцюжки
    `TextBuilder`. Те, що дають таблиці рядків (`_S`, `_T`), — їхнє.
  - Самі частини гри зберігають англійське, з яким порівнюють: Wings перевіряє «Jump» на події, ще до запису.
    Тому `Jump` у Strings лишається англійським (`held.tsv`), а на панелі стоїть «Стрибок» із `Abilities`.
  - Опис гра складає наново з шаблону `ActivatedAbilities` з числами (`GameObject.DescribeActivatedAbility`, при
    зміні рівня, стійки, спорядження). Шаблон український, а рядки, які під ним дописує
    `Templates.StatCollector`, — англійські: «Cooldown reduced by 5 due to Сила волі: висока.», «Damage increased
    by 1-2 due to high strength.» (гра 2026-10-04). Постфікс на всіх трьох `DescribeActivatedAbility` пускає опис
    через `Abilities` рядок за рядком. Ключі цих рядків дає `codescan.postfix_keys`: формати з методів
    `StatCollector` (`AddChangePostfix` тощо, з передаванням одного одному) з тим «що» й «чому», яке дає кожен
    виклик (тернарна причина — обидві: «high strength» / «low strength»); 53 ключі. Переклад однією формою:
    «Перезаряджання: на 5 менше (Сила волі: висока).», «Шкода: на 1-2 більше (висока Сила).».
  - Значення характеристики, яке код ставить англійською (`StatCollector.Set`: «Дальність: sight», «Кидок проти
    падіння: Strength 21»), перекладається, лише поки рендериться (`XMLTemplateReplacers.Value`: вузли `stat` і
    `statline`, не `switch`): слово з `Words` (`codescan.scan_words` бере такі значення з `stats.Set`) або назва
    характеристики перед числом («Сила 21»). Потім у колекторі знову англійське — для `switch`, що його порівнює.

- `MinerPatches`: робот-мінер називає себе за гранатою, яку ставить (`Miner.SetupMinerConfiguration`): код
  обрізає назву гранати на «grenade» і дописує «miner mk II» / «bomber mk II». В українській назві «grenade»
  немає, тож виходило «{{W|фугасна}} граната Mk I miner mk I». Тепер вид міни — назва гранати без «граната» й
  марки («{{W|фугасна}}», «газова {{normal|нормальності}}», «{{B|ЕМІ}}» з «ЕМІ-гранати»); робот — прикметники в
  чоловічому роді й іменник із `Words` («miner» → «мінер», «bomber» → «підривник»): «{{W|фугасний}} мінер Mk I»;
  здібність — «Поставити міну [{{W|фугасна}} Mk I]», міна в описі — «{{W|фугасна}} Mk I». У грі не перевірено.

- `SkillPatches`: рядок здібності, яку ще не вивчено, у списку навичок: «Притискний вогонь [200 ОН] 25 Спритність,
  Draw a Bead». Потрібну здібність гра називає англійським `Name` запису (`SPNode.ModernUIText`), хоч виняток
  поруч бере `GetDisplayName`. Постфікс замінює в рядку `Name` кожного потрібного запису його назвою з перекладу.
  Зайва кома в «[300 ОН] , 29 Сила … або , 29 …» — від самої гри (`PowerEntryRequirement.Render`), в англійській
  так само.

- `DidXPatches`: розповідь, яку гра складає сама з дієслова (`Messaging.XDidY`, `XDidYToZ`, `WDidXToYWithZ`,
  472 місця в коді: «X dies!», «You begin healing.»). Префікси запам’ятовують виклик, а єдиний для них
  `HandleMessage` замінює англійський текст шаблоном нашої граматики з таблиці `DidX`
  (`=subject.Name= =subject.v:помирає:помираєте:помирають=!`). Ключ таблиці — `вид|дієслово|прийменник|
  непрямий прийменник|extra|кінцевий знак`; перекладач бачить англійською «<subject> die!».
  - Поле, яке обчислює код, сканер розв'язує:
    - локальну змінну — тим, що їй присвоює метод;
    - поле класу — його літералами, а `…Stripped` — без розмітки;
    - решту — одним пропуском («begin {0}!»).
  - Дієслово з даних гри (`Projectile.PassByVerb`, `BootSequence.VerbOnBoot*`, перемикачі, гранати; поля з
    їхніми усталеними значеннями й атрибути креслень) потрапляє в таблицю `Verbs`, де в нього три форми
    («свистить:свистите:свистять»). Повідомлення, яке гравець читає з DidX, отримує ключ із `*` на місці
    дієслова. Перекладач бачить «<subject> <verb> past <object>!» і ставить `{v}`. Якщо в дієслова немає
    власного ключа, мод бере шаблон із `*` і підставляє `=subject.v:форми=` (`DidX.Template`).
  - У шаблонах Strings дієслово з даних гри — `=verb|uk.v#subject=` (`UkrainianPostProcessors`): форма з
    таблиці `Verbs` для того, хто діє. Невідоме дієслово лишається як є.

- `DamagePatches`: кінець рядка шкоди («You take 5 damage from %t bite.»). Код передає `TakeDamage` хвіст із
  кодами (`%t` — чиє це було), а `Physics.ProcessTakeDamage` заповнює їх англійською («your», «the snapjaw's»)
  і ставить попереду голову («You take 5 damage», вона є в `Text`). Префікс бере хвіст раніше: таблиця
  `Damage` (`codescan.scan_damage`) дає його з нашою граматикою, де `=object.…=` — той, хто завдав шкоди, а
  `=subject.…=` — той, хто її отримує: «від =object.p:вашого укусу:укусу (@):укусу=.» → «від вашого укусу.»,
  «від укусу (пащеклац).». Третя форма `p` — коли винного немає (може бути порожньою: «від вогню
  =object.p:(ваш):(@):=!» → «від вогню!»). Хвіст, який загальний ключ («from %t {0}!» газу) узяв з англійським
  словом у пропуску, лишається, як його пише гра, і йде в журнал як `[uk-miss]`.

- `JournalPatches`: досягнення гравця, які код пише англійською (`JournalAPI.AddAccomplishment`): запис у
  журналі («You journeyed to Golgotha.» → «Ви вирушили до Голгофи.»), фреска в гробниці гравця й євангеліє,
  яке переказують села наприкінці. Таблиця `Journal` (`codescan.scan_journal`). Фреска й євангеліє — про
  гравця в третій особі, минулий час з `=player.g:…=`, як у `HistorySpice` (docs/history.md, 6b);
  `AddAccomplishment` сам розгортає їхні `<spice…>` і `=…=`.

- `RulesPatches`: рядки правил під описом предмета чи істоти, які код пише англійською («Keen: +2 to
  penetration rolls», «Requires training in {0} to use.»). Усі вони проходять `Extensions.AppendRules`
  (п’ять перевантажень із самим текстом), тож перекладаються там, за таблицею `Rules` (`codescan.scan_rules`).
  Для нових таблиць (`Abilities`, `Fragments`, `Rules`) сканер розгортає й тернарний вираз усередині
  конкатенації: «… on hit» і «… on hit {2}% of the time» — окремі ключі, а не один із пропуском.

- Текст, який код складає будівником у `if`/`else`, сканер проходить кожним шляхом
  (`codescan.builder_paths`; однакова умова на шляху має одне значення). Локальна змінна з параметра події
  (`E.GetStringParameter("ShowDamageType", "damage")`) дає своє усталене значення й ті кілька, що код туди
  передає. Так таблиця `Text` отримала:
  - удари ближнього бою, які `Combat` передає в `TakeDamage` як `Message` (`Physics` ставить ім’я нападника
    замість `%T`): «Ви влучаєте (x2) і завдаєте 5 шкоди (кинджал)! [17]», «Пащеклац влучає у вас (x1) і
    завдає 3 шкоди (щелепи). [12]»;
  - голови рядків шкоди («Ви отримуєте 5 шкоди …», «… отримує 5 {{icy|шкоди від холоду}} …»);
  - зміни репутації («Ваша репутація (Джоппа) зросла на 50 і тепер становить 250. Джоппа тепер ставиться
    до вас прихильно.»; слово ставлення — з `Words`), поклоніння й богохульство, кілька запитів.

- `TextPatches`: спливні вікна, відмови й журнал повідомлень (`Popup.ShowBlock`, `PopupMessage.ShowPopup`,
  `Popup.PickOption`, `MessageQueue.AddPlayerMessage`) — через таблицю `Text`. Текст без англійської (його вже
  переклали таблиці рядків) проходить одразу; результати пам’ятаються.
  - Варіанти `PickOption`, які метод спершу складає в локальний масив чи список (`options = new string[5] {…}`,
    `list.Add(…)`), і вступ над ними (другий аргумент) сканер теж бере: системне меню («Зберегти й вийти»,
    «Призначення клавіш»), «На якій відстані … має йти за вами?», варіанти перейменування. Масив усередині
    іншого аргументу (`HotkeySpread.get(new string[2] { "Menus", "UINav" })` — шари введення) — не варіанти.
    Будівник з `AppendPrefixed` (список модів) дає перший рядок окремим ключем.
  - Кнопка фільтра «ALL» в інвентарі — константа самої кнопки (`categoryTextMap`), її текст і підказка — з
    `Words`.
  - Мітки з префаба Unity, яких немає ні в коді, ні в таблицях: «delete» і «Mods Differ» у рядку збереження
    (`SaveManagementRow.setData`, `UITextSkin` під ними). Слова — `codescan.PREFAB_WORDS` → `Words`. У грі ще
    не бачено: якщо мітка не `UITextSkin`, нічого не зміниться.
  - Режим гри в рядку збереження («Рівень 1, Roleplay») — ID зі стану `GameMode`. Переклад рядка Strings
    пропускає його через `=gamemode|uk.word=`, а `uk.word` тепер шукає й у `Words`: «класичний режим».

Перевірка без гри: `dotnet build tools/grammar-build`, потім `dotnet run --project tools/patch-tests`. Стенд
вантажить збірку гри й DLL мода, застосовує патчі (Harmony тієї ж версії, що в грі, але для .NET) і викликає
справжні методи гри.

## Як перевіряється

1. **Компіляція без гри:** `dotnet build` проєкту `tools/grammar-build/`, який посилається на
   бібліотеки гри з `CoQ_Data/Managed` за шаблоном `Mods.csproj.template.txt` (`netstandard2.0`,
   C# 9). Сама гра компілює ці файли з моду.
2. **Тести логіки:** консольний тест-раннер без NuGet (`dotnet run`), лише чисті класи.
3. **У грі** — лише з дозволу Mike (гру без нього не запускаємо):
   - wish `testlangreplacers`;
   - бойові повідомлення;
   - повідомлення від імені гравця.

## Порядок

1. Провайдер + `v`, `g`, `plural`: компіляція й тести.
2. `validate` знає нові ключі; перекладачі отримують цей синтаксис.
3. Переклад граматичних рядків `Strings`; переписати обхідні з пакетів 02–07.
4. Відмінки назв: дані з перекладу (рід, форми) + узгодження прикметників у `DescriptionBuilder`.
5. `HistorySpice.uk.json` і процедурна історія.
6. Перевірка в грі.
