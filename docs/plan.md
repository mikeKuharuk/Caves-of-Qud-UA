#### Підсумок
- Основний шлях працює: дані, таблиці рядків і довідка перекладаються самим фреймворком, без
  жодного рядка C#.
- Для граматики є офіційні точки: `[LanguageProvider("uk")]` (артиклі, списки, числа, назви
  об'єктів, перенос рядків) і `[HasVariableReplacer(Lang = "uk")]` (займенники, дієслова, множина
  через наші ключі).
- ⚠️ Шрифти:
  - у пропорційних елементах UI кирилиця береться з іншого, моноширинного шрифту, тож ширини
    не збігаються з латиницею;
  - довгі пункти меню обрізаються;
  - у класичному UI літери дрібні й розріджені.
  Це етап 7.
- ⚠️ Переклад рядка з одним Context може з'явитися в іншому місці з тим самим англійським ID
  (загальна таблиця за ID). Треба пам'ятати, коли однакові англійські слова потребують різних
  перекладів.
- **Не перевірено:**
  - плаваючий текст на карті (у сучасному UI);
  - чи працює `Languages` у `Directories` для C#-коду під час завантаження (до
    `GameManager.Playing` мова = `en`);
  - поведінка на macOS/Linux.

## Етап 2 — Інструменти ✅ (2026-09-28, крім CI та глосарію)

Усе в `tools/qud.py` (модулі `tools/qudtr/`, тести `tools/tests/`, лише стандартна бібліотека
Python). Порядок роботи — в `docs/style-guide.md`, розділ «Робочий цикл».

- [x] Формат джерела перекладу — PO (рішення **D5**). Власний модуль `po.py`: детермінований
      вивід, `fuzzy`, `#| msgid`, застарілі записи `#~`.
- [x] `tools/misses.py`: збирає промахи таблиці рядків із `Player.log`.
- [x] `sync`: ExampleLanguage (з гри або з тегу дзеркала) → `translations/uk/*.po`.
  - нові одиниці додаються;
  - змінений англійський текст → `fuzzy` зі старим перекладом і `#| msgid`;
  - зниклі одиниці → `#~`;
  - ключі елементів беруться зі схеми в заголовку кожного example-файлу (`Name="Key"`).
- [x] `build`: PO → `mod/Language/*.uk.xml`. Правила залежать від того, як завантажувач
      обробляє повторне визначення:
  - `objects` (атрибути зливаються поштучно) — лише перекладене;
  - інші файли — запис верхнього рівня цілком (англійською, де ще не перекладено), бо
    завантажувач може замінити все визначення (BookUI очищає сторінки книги);
  - позиційні списки (сторінки, склади імен) — все або нічого.
- [x] `validate`:
  - **помилки:** залишки `▶`, незбалансовані `{{ }}`, невідомий шейдер, змінені клавіші
    `~Cmd…`, змінені ключі складених значень;
  - **попередження:** `=змінні=`, коди кольорів, кількість `~`-варіантів, пробіли на кінцях,
    латиниця в кириличному слові, апостроф не `’`.
- [x] `stats`: прогрес по файлах. `import`: наявні `*.uk.xml` → PO.
- [x] Тести (44):
  - кожне правило валідатора перевірено і на хорошому, і на поганому перекладі;
  - «build → import» на всіх 40 реальних файлах. Цей тест тричі впав на справжніх помилках
    (порожні одиниці, позиційні сторінки книг, ключі не зі схеми) — їх виправлено.
  - перехід 212.30 → 212.31 на дзеркалі, де «перекладено» все: жоден переклад не губиться,
    змінені рядки стають fuzzy. Тест на повернення застарілого рядка спіймав ваду (переклад не
    відновлювався) — виправлено.
  - повторні `sync` і `build` дають байт-у-байт той самий результат.
- [ ] (Опційно) GitHub Actions: `unittest` + `validate` на кожен push.
